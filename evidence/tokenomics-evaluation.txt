[Retrieval] Describe the cloud migration approach.
Route: retrieval
Answer: ## Cloud Migration Approach

Based on information provided by the **Retrieval Agent**, sourced from **`cloud-migration-playbook.pdf`** and **`q2-2026-client-report.pdf`**, here is a description of the cloud migration approach:

---

### Overview
Acme Consulting's cloud migration approach is structured around **four phases**, designed to transition a client's on-premises data infrastructure to a cloud platform.

---

### Phase 1: Discovery and Assessment
*(Source: cloud-migration-playbook.pdf)*

The process begins with a **2–4 week discovery phase** that inventories existing systems, data volumes, and integration points. Key deliverables include:
- A system inventory
- A data classification summary
- A preliminary risk register

> ⚠️ **Important note:** Integration complexity should not be underweighted relative to raw data volume — a small database with many integrations can be harder to migrate than a large one with few.

---

### Phase 2: Migration Strategy Selection
*(Source: cloud-migration-playbook.pdf)*

Three strategies are available depending on downtime tolerance and system complexity:

| Strategy | Description | Best For |
|---|---|---|
| **Lift-and-Shift** | Fastest option; carries forward existing schema issues | Simple migrations |
| **Re-platform** | Modernizes schema during migration | Clients with known data quality issues |
| **Parallel-Run** | Both systems run simultaneously | Near-zero downtime tolerance (e.g., transaction systems) |

---

### Phase 3: Execution
*(Source: cloud-migration-playbook.pdf, q2-2026-client-report.pdf)*

- Migrations are executed **in batches** — never as a single cutover — to allow validation checkpoints and limit failure impact.
- Each batch is validated against **source-system checksums**.
- A **rollback plan must exist for every batch**.
- **Daily client communication** is maintained throughout.

---

### Phase 4: Validation and Cutover
*(Source: cloud-migration-playbook.pdf)*

Before final cutover, a full reconciliation is run between source and target systems, including:
- Record counts
- Checksums
- Functional testing of downstream applications

> ⚠️ **Important note:** Known data quality issues should be **remediated before cutover**, as post-migration fixes are typically more costly.

---

**Sources Cited:** `cloud-migration-playbook.pdf`, `q2-2026-client-report.pdf` (via Retrieval Agent)
