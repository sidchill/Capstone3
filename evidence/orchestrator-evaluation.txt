[Retrieval] Describe the cloud migration approach.
Route: retrieval
Answer: ## Cloud Migration Approach

Based on the retrieved information, Acme Consulting's cloud migration approach is structured around **four key phases**:

---

### Phase 1: Discovery and Assessment
This initial phase lasts **two to four weeks** and focuses on inventorying existing systems, data volumes, and integration points. Key deliverables include a system inventory, data classification summary, and a preliminary risk register. An important guiding principle here is that **integration complexity should be weighted heavily** — a small database with many downstream integrations can be more challenging to migrate than a large database with few connections.

---

### Phase 2: Migration Strategy Selection
Three strategies are available, chosen based on downtime tolerance and system complexity:
- **Lift-and-shift** – Fastest option, but carries forward existing schema problems
- **Re-platform** – Modernizes the schema during migration; most common for clients with data quality issues
- **Parallel-run** – Both systems operate simultaneously; recommended when downtime tolerance is near zero

---

### Phase 3: Execution
Migrations are executed in **batches** (never as a single cutover), with validation checkpoints between each stage. Every batch is validated against source-system checksums, rollback plans must exist for every batch, and **daily client status updates** are recommended throughout.

---

### Phase 4: Validation and Cutover
A full reconciliation between source and target systems is performed, covering record counts, checksums, and functional testing. Critically, known data quality issues should be **remediated before cutover**, as fixing them post-migration is typically more expensive.

---
